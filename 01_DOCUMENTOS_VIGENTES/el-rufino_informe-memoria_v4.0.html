✨ Mythos — El modelo ideal para El Rufino Un modelo que combinara la profundidad estratégica de Opus con la velocidad de Haiku, memoria persistente real del historial del proyecto sin necesidad de pastear contexto, comprensión profunda del periodismo local latinoamericano y la realidad territorial argentina, capacidad de generar imágenes con tipografía controlada en el mismo workflow, y publicación directa a WordPress vía API.   • Prompt maestro en 00_CONTEXTO_IA/

  • GitHub como memoria persistente real
  • Agente 11 genera prompts para Gemini/MJ

  • Modelos multimodales de mayor precisión
  • MCP servers para WordPress + Claude

09 · Manual de procedimientos

Cómo trabajar mejor con IA

Protocolo construido desde la experiencia real del proyecto. Cada regla tiene una razón concreta detrás — y en general un error cometido que la originó.

Protocolo de inicio de sesión

1

Cargar solo 00_CONTEXTO_IA/ al inicio

La carpeta de contexto es la fuente única de verdad. Cargar archivos binarios o carpetas pesadas (03_IDENTIDAD_MARCA) consume contexto sin aportar información útil. Máximo 3 archivos por sesión: prompt maestro + repositorio + el archivo específico de la tarea.

2

Declarar el objetivo de la sesión en el primer mensaje

No arrancar con "hola" ni preguntas generales. Ir directo: "Sesión de hoy: configurar child theme Newsup con paleta B. Plugin v8.1.2 activo. Necesito style.css y functions.php." Esto ahorra 3–5 intercambios de contextualización.

3

Elegir el modelo correcto antes de empezar

Estrategia → Opus. Código y redacción → Sonnet. Variantes rápidas → Haiku. Usar el modelo equivocado no es solo más caro: puede ser más lento para tareas que no lo requieren. Haiku genera variantes 3x más rápido que Sonnet para titulares simples.

4

Hacer checkpoints cada 30–40 mensajes

Las conversaciones largas degradan la calidad porque el modelo pierde el hilo del contexto inicial. Cada 30–40 mensajes: guardar en GitHub, abrir sesión nueva con el contexto actualizado. No esperar a que la sesión "se rompa".

5

Versionar y guardar en GitHub antes de cerrar

Nunca cerrar sin subir lo producido. El protocolo PowerShell para upload está en 00_CONTEXTO_IA/. ASCII-only, ejecutar Set-ExecutionPolicy primero, hacer GET para obtener SHA antes de PUT en archivos existentes.

6

Actualizar el prompt maestro con cada decisión nueva

Toda decisión que cambie el estado va al prompt maestro ANTES de terminar la sesión. Si se cierra sin actualizar, el contexto de la próxima sesión será incorrecto — esto causó retrabajo real en el proyecto.

Reglas de ahorro de recursos

❌ Qué no hacer

  • Cargar archivos binarios al contexto
  • Pedir al modelo que "recuerde" sin cargar contexto
  • Usar Opus para código rutinario
  • Sesiones de 100+ mensajes sin checkpoint
  • Repetir el contexto desde cero en sesiones nuevas sin usar el archivo de contexto
  • Solicitar variantes de lo mismo en el mismo mensaje
  • Exponer tokens de GitHub en el chat

✅ Qué sí hacer

  • Un objetivo claro por sesión
  • Contexto mínimo necesario, no el máximo posible
  • Separar sesiones de código de sesiones de estrategia
  • Haiku para primeras iteraciones, Sonnet para el definitivo
  • Prompts estructurados: contexto → tarea → restricciones → entrega esperada
  • GitHub como memoria entre sesiones
  • Documentar errores conocidos para no repetirlos

12 · Seguridad y 2FA

Cómo proteger el proyecto

El proyecto tuvo un incidente real de exposición de token. Esta sección convierte esa experiencia en protocolo concreto y no negociable.

Incidente documentado — Token GitHub expuesto en chatDurante una sesión, un token de GitHub fue expuesto en texto plano. Fue revocado y regenerado inmediatamente. Lección: los tokens van en variables de entorno en scripts — nunca en el chat con la IA.

¿Dónde implementar 2FA?

✅ 2FA obligatorio

  • GitHub org ElRufino — todas las cuentas con write
  • Google (cuenta principal) — propietaria del Drive y storage
  • Hostinger — acceso al hosting de producción
  • WordPress admin — cuentas con rol Admin (C1 y C2)
  • NIC Argentina — cuenta registrante del dominio

🟡 2FA recomendado

  • Cuentas de Claude.ai de colaboradores
  • Email corporativo del proyecto
  • Cuentas de redes sociales (FB, IG, TikTok)
  • Google Drive de cuentas colaboradoras
  • Cuenta de Gemini para generación de imágenes

Protocolo de tokens GitHub

1

Fine-grained tokens siempre

No usar tokens clásicos con scope repo completo. Fine-grained: "Contents: Read and write" + "Metadata: Read-only". Alcance mínimo necesario.

2

Nunca pegar el token en el chat con la IA

Si por error se expone: GitHub → Settings → Developer settings → Personal access tokens → Revocar. El historial del chat no puede borrarse del lado del servidor.

3

Rotar tokens cada 90 días

Configurar fecha de expiración en 90 días. Anotar la fecha de vencimiento en el CHANGELOG del repositorio.

4

Un token por función

Token para upload de contexto. Token separado para la Claude API del plugin. Si uno se compromete, el otro sigue funcionando.

🔑 Checklist de seguridad

  • ☐ 2FA en GitHub (cuenta C1 owner)
  • ☐ 2FA en Hostinger
  • ☐ 2FA en Google (cuenta principal)
  • ☐ 2FA en NIC Argentina
  • ☐ Tokens con fecha de expiración
  • ☐ Tokens separados por función
  • ☐ Protocolo de revocación documentado
  • ☐ WP admin solo vía HTTPS
